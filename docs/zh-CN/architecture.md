# 架构

> 本文是 [Architecture](../architecture.md) 的中文翻译。

## 系统契约

给定一项自然语言任务和一个本地工作区，可信 CLI 会在必要时准备 Git 基线。随后，智能体可以检查文件、执行有边界的编辑、运行经过审批的命令，并基于真实工具结果反复迭代。最终，它会返回经过验证的变更、不产生修改的信息性回答，或者明确的受阻、失败或取消状态。

首个版本面向小型缺陷修复和小型功能扩展，不以多仓库操作、部署、GUI 自动化、长时间运行任务或多智能体协作为目标。

## 深模块与接缝

`AgentEngine.run(TaskRequest) -> RunResult` 是主要的外部接口。其实现负责循环、状态转换、重试预算、上下文视图、停滞检测、验证新鲜度和终止状态。

`LocalAgentRunner.run(objective) -> RunResult` 是单次命令和交互式命令共同使用的本地应用接口。每次调用时，它都会创建新的运行 ID、事件、制品、工具和 `AgentEngine`，因此交互式会话的不同轮次不会共享控制器状态或验证证据。

`ConversationStore.create/resume/list` 与 `ConversationSession.prepare/record` 负责持久化的对话标识、工作区绑定、JSONL 校验、脱敏和自动上下文压缩。它们提供的小型接口使终端和 CLI 无需依赖具体的持久化格式。

会话发现只包含至少完成过一轮对话的会话。刚创建但尚无轮次的会话会在退出时，或 TUI 切换到已保存会话时被安全丢弃；该清理路径绝不会移除已完成会话的日志。

`InteractiveSession.run(run_task) -> int` 负责终端语法、斜杠命令和界面呈现。它把历史记录和有边界的上下文交给一个 `ConversationSession`；仓库始终是权威状态来源，每次请求都通过同一个 `LocalAgentRunner` 接口。

`TerminalPrompt.readline(prompt) -> str` 负责可编辑的终端输入和斜杠命令选择器。它封装 Windows/POSIX 按键解码、Unicode 显示宽度、菜单筛选、光标移动，以及输入重定向时使用的行模式回退方案。

`TerminalTheme` 负责 ANSI 能力检测，并为欢迎面板、提示符、菜单、进度、终止状态和审批卡片提供统一的视觉语言。它是一个纯展示接缝：调用方提供长度受限的文本，并继续负责全部会话、策略和控制器行为。重定向输出和 `NO_COLOR` 会绕过样式化展示，但不会改变事件或审批语义。

对于面向用户的控制台运行，一个仅用于展示的 `ModelPort` 包装器会在每次 `complete(...)` 调用前后调用 `ConsoleEventSink.begin_model_request/end_model_request`。这样可以显示一条临时工作指示，而无需增加控制器状态或改变结构化事件协议。

`describe_tool(...)` 和 `describe_tool_result(...)` 会把不可信的工具参数及结果投影为有界且不含原始内容的进度说明，供事件与审批摘要共同使用。

`load_user_settings(path) -> UserSettings` 是用户级配置边界。它负责固定路径、受大小限制的 UTF-8 JSON 解码、完整模式校验、相对运行目录和会话目录的解析，以及不会泄露密钥的错误信息。CLI 只接收经过校验的不可变值对象。

每个内部接缝至少有一个生产适配器和一个测试适配器：

| 接缝 | 生产适配器 | 测试适配器 |
|---|---|---|
| 模型 | `OpenAICompatibleAdapter` | `ScriptedModelAdapter` |
| 工具 | `LocalToolRuntime` | 场景替身 |
| 审批 | 终端提示/限定范围的策略 | 固定决策 |
| 事件 | JSONL/控制台 | 内存事件接收器 |
| 时钟 | 系统时钟 | 虚拟时钟 |
| 终端 | 原始按键提示及行模式回退 | 注入的按键读取器/文本流 |
| 用户配置 | 固定的用户级 JSON 文件 | 临时 JSON 文件或值对象 |
| 对话 | 带锁的用户级 JSONL 存储 | 临时目录存储 |

供应商响应、子进程对象和 CLI 渲染信息不会进入核心数据模型。

模型适配器通常会在 HTTP 协议层要求工具调用。提供显式 Thinking 模式的供应商可能拒绝强制工具选择，因此 `thinking=enabled` 会改用自动工具选择。这只放宽供应商请求参数。部分兼容供应商即使收到只请求一个动作的提示，也可能返回多个工具调用。适配器会确定性地只选择并校验第一个调用，记录原始提案数量，并丢弃其余调用。因此，在任何动作执行之前，`AgentEngine` 仍然只会收到一个列入允许列表的结构化动作。

## 配置启动

常规命令会在工作区初始化之前加载 `~/.coding-agent/settings.json`。显式 CLI 值覆盖文件值，文件值覆盖兼容的环境变量，最后才使用内置默认值。配置文件是可选的；但如果存在，就必须是仅使用已记录字段的 JSON 对象，并且不得超过 64 KiB。帮助输出不会加载配置文件，因此错误配置无法遮蔽修复说明。

直接提供的 API 密钥只会传入模型适配器和脱敏器。它不会出现在配置错误或对象字符串表示中，也不会进入模型可见上下文或允许子进程继承的环境变量列表。

## 工作区启动

在构造 `AgentEngine` 之前，CLI 会校验模型配置并调用 `prepare_workspace(path)`。已有的 Git 根目录会被严格保持不变。对于非 Git 目录，系统会使用保护凭据并适配项目类型的忽略规则初始化仓库，然后把所有未被忽略的文件纳入初始提交。若目录位于另一个仓库内部，系统会拒绝操作，而不会悄悄扩大工作区范围或创建嵌套仓库。

这条启动路径是可信的、由用户明确请求的编排。它使用有边界、无需 Shell 的 Git 子进程和经过过滤的环境变量。该能力不会作为模型工具暴露；智能体循环中的 Git 操作仍然是只读的。

## 控制器循环

```text
INITIALIZING
  -> REQUEST_MODEL
  -> VALIDATE_ACTION
     -> RESPOND -> ANSWERED
     -> EXECUTE_TOOL -> RECORD_OBSERVATION -> REQUEST_MODEL
     -> VERIFY_FINISH -> SUCCEEDED
     -> BLOCKED
  -> FAILED | CANCELLED
```

模型的每一轮响应都必须规范化为以下类型中的一个且仅一个：

```text
ToolCall | AnswerRequest | FinishRequest | BlockedRequest
```

如果供应商响应包含多个工具调用，适配器边界会将它串行化：只规范化第一个调用，后续调用全部丢弃，不会被校验或执行。下一次模型请求会基于真实执行结果和当前工作区重新构建，因此其余操作必须重新提出。动作事件会记录 `proposed_actions` 以供审计。没有工具调用、第一个工具未知，或者第一个调用参数格式错误的响应仍然属于协议错误；控制器允许模型在有界次数内纠正，但不会执行任何不完整动作。

`max_model_turns` 限制正常工作决策的轮数。如果最后一个允许的工作决策产生了最新的完成证据，控制器会额外提供且仅提供一次终结决策，而不会在模型引用该证据之前就判定失败。该决策只暴露 `finish` 和 `report_blocked`；一旦 `finish` 被拒绝或模型提出任何非终止动作，运行就会结束，工作循环也不能重新开启。没有当前有效证据或已经超出总时间预算时，不会提供这次宽限决策。

另外两种更早介入且由控制器管理的模式会保护最终预算。跨工具连续执行八次只读动作后，会启动一次性的进展门禁并隐藏所有检查工具。当工作区已经发生变更且只剩四个正常轮次时，运行会进入收尾模式，并在剩余期间永久隐藏源代码检查和修改工具。收尾模式只暴露验证、验证输出读取、`finish` 和 `report_blocked`；即使适配器返回被隐藏的工作动作，也不能执行。

## 工具执行

模型可以看到十三个本地工具：

```text
list_directory  read_file      search_text
edit_file       write_file     create_file    delete_file
run_command     git_status     git_diff
browser_check   read_output    search_output
```

模型还可以看到三个控制器动作：`respond`、`finish` 和 `report_blocked`。对于不需要修改工作区的对话或信息性目标，`respond` 会以 `ANSWERED` 状态结束。如果已经记录到任何工作区修改，控制器会拒绝 `respond`，因此它无法绕过 `finish` 的验证门禁。

文件系统路径必须相对于工作区。实现会先解析路径穿越、符号链接和连接点，再检查是否仍位于工作区内。系统会拒绝直接访问 `.git`、`.coding-agent` 和可能包含凭据的文件。小范围编辑必须同时提供预期文件哈希，并保证旧文本片段恰好匹配一次；整文件替换使用单独命名的操作，并需要审批。写入过程先写入临时文件，再原子替换。修改已有文件前，系统会先保存完整的修改前快照；如果无法精确且有界地恢复，则停止修改。由于 Git 无法恢复原本就未跟踪的目标，审批信息会特别标明此类文件。

命令以“程序 + 参数数组”的形式运行，并设置 `shell=False`。子进程只接收一个不包含模型 API 密钥的精简环境变量允许列表。除非启动策略预先授权了某个可执行程序，否则命令执行、浏览器渲染、整文件替换和删除都需要审批。输出会被限制大小、脱敏并保存为制品，再通过预览和分页读取提供给模型。

面向用户的进度事件会携带有边界的工具目标或可观察结果，而不是原始内容或命令参数。审批界面首先显示同样简洁的说明、操作系统账户风险和短摘要。用户可以要求查看完整的脱敏 JSON 参数和完整摘要；只有明确的肯定回答才会批准操作。

`browser_check` 会解析一个工作区内的 HTML 文件，使用一次性配置目录启动由控制器选择的 Edge、Chrome 或 Chromium 可执行文件，在有边界的视口中进行渲染，保存脱敏 DOM 和大小受限的本地 PNG，并创建一条 `browser` 验证记录。模型只会得到不透明的截图 ID，而不是本地绝对路径。浏览器执行需要常规执行审批。

## 状态与上下文

事件日志和 `RunState` 是权威状态。提示词是一个有界的派生视图，包含：

- 原始目标和不可变规则；
- 工作区版本及变更路径；
- 最近的验证记录和错误；
- 最近的工具动作及规范化观察结果；其中字节完全相同的只读观察会被去重，同一工作区版本内已覆盖的 `read_file` 范围会直接从控制器内存返回；
- 当前工具模式定义。

派生状态还会报告 `completion_evidence_ready`。只有当前工作区版本具备控制器要求的验证证据时，它才会变为真；对于可视化 Web 工作，还必须具有浏览器证据。该字段只是终结提示，并不声称实现的语义一定正确；后续任何修改都会使原有证据过期。

派生状态还会报告剩余工作轮数、连续只读动作数量、`progress_required` 和 `wrap_up_mode`。这些字段说明可用工具为何会收窄，但模型文本无法借此改变控制器模式。

旧事件即使从模型视图中移除，仍会保存在磁盘上。仓库内容和工具输出均被视为不可信数据，不能授予新权限。

交互式连续性是围绕各个独立运行构建的另一层。每个已完成轮次都会追加一条脱敏记录，其中仅包含请求、助手结果、终止状态、运行 ID 和变更路径名称。恢复操作会校验 32 位十六进制 ID，并要求工作区与记录的原始规范工作区一致。它不会恢复正在执行的引擎、审批、工具观察、预算或验证记录。

在执行后续请求前，对话存储会在硬字符预算内渲染最近轮次。当内容超过目标大小时，它会确定性地把最早的轮次折叠为持久化的结构化摘要，同时保留近期原始轮次。自动压缩不需要额外调用模型。恢复的文本会被标记为不可信内容，不能覆盖当前仓库或控制器状态。

## 验证新鲜度

每次检测到工作区变更时，`workspace_version` 都会递增。`VerificationRecord` 保存验证命令、退出码、输出制品、结果和工作区版本。后续源代码变更会使旧证据过期。

只有满足以下条件，模型提出的 `finish` 请求才会被接受：

1. 至少记录到一项工作区变更；
2. 引用的每个验证 ID 都存在；
3. 至少有一项被引用的验证在当前版本上通过；
4. 控制器能够检查完整且非空的最终 Git 差异，其中包括新增且未跟踪的 UTF-8 文件内容。

如果变更涉及 Web 文件，且当前目标表明任务与可视化界面、动画、游戏、布局或交互有关，那么引用的证据还必须包含当前工作区版本上成功的 `browser` 验证。单纯的命令语法检查不能满足这一专用门禁。

控制器能够证明证据是在当前状态上运行的，但不会声称有限测试套件可以证明语义完全正确。

`ANSWERED` 是独立的非修改终止状态。只要工作区尚未发生修改，即使已经进行过只读检查，该状态也合法；它不表示代码变更已经过验证。

## 错误与重试策略

临时模型传输失败使用有界指数退避。身份验证错误和格式错误的请求不会重试。对于空动作或格式错误的模型动作，系统会在很小的次数限制内提供结构化反馈。文件冲突、命令失败、超时、审批拒绝和策略拒绝都会转化为观察结果；非幂等的本地动作绝不会自动重试。

当正常模型轮次预算耗尽但存在最新完成证据时，系统可以在剩余总时间预算内执行一次仅用于结束的模型决策。控制台用 `[FINALIZE]` 标记这一转换。传输层重试仍被限制在这一个逻辑决策内；控制器不会在终结模式中执行新的工作工具。

成功的文件读取会形成一次运行内、按工作区版本隔离的缓存。后续对已完全覆盖范围的请求会收到所需切片和一条 `CACHED` 观察，而无需再次访问文件系统。连续两次命中缓存后，控制器会在下一次模型决策中暂时隐藏 `read_file`，迫使交替读取范围的循环选择编辑、其他检查机制、验证、回答或明确报告受阻。任何记录到的工作区修改都会通过推进版本使缓存失效；不相交或尚未覆盖的范围仍可正常执行。

更广泛的进展计数器会跨越全部只读工具，包括缓存动作和跳过的动作，因此交替执行 `read_file`、`search_text` 和 Git 观察也不能重置它。写入或执行决策会重置计数器。接近轮次上限时，收尾模式优先于临时进展门禁，并把剩余决策保留给当前状态的验证和终止操作。

对于其他只读工具，连续第二次提出相同动作会被跳过，并转化为结构化纠正观察；第三次相同动作会触发专用的 `STAGNATION` 终止错误。动作指纹包含工作区版本，因此后续修改会使旧观察失效。模型轮数、总时间、命令时间、输出量和协议错误均由控制器设置限制。工具事件会分别记录总耗时、审批等待耗时和实际执行耗时。协议警告会保留长度受限的准确拒绝原因，并经过常规脱敏边界。

## 评测

评测不会只信任 `RunResult`。每个任务都会从全新的 Git 固件开始。智能体停止后，系统会注入隐藏文件，并在智能体循环之外运行独立的判定器命令。如果智能体声称成功但判定器失败，该结果会被明确计为虚假成功。只有 `SUCCEEDED` 才可能通过编程评测；`ANSWERED` 始终不能算作通过。

## 已知限制

- 没有操作系统沙箱或容器沙箱；
- 运行过程中发生崩溃时，不能通过检查点恢复尚未完成的运行；只能恢复已经完成的对话轮次；
- 对经过审批的子进程不提供自动网络隔离；
- 无头浏览器检查可以获取渲染证据，但不能对主观视觉质量进行语义判断；
- 不支持并行工具或多智能体协作；
- 采用面向行的终端界面，而不是全屏编辑器；
- 不支持多个进程并发使用同一个对话会话；
- 不支持模型逐 Token 流式输出；
- 只支持编辑 UTF-8 文本；
- 针对小型仓库和有边界任务进行了优化；
- 启发式密钥检测可能存在漏报；
- 首个版本只有一个兼容 OpenAI Chat Completions 的适配器；
- 只有一个固定的用户级配置文件，不支持项目级配置层。
