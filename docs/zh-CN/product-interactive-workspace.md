# 产品设计：交互式 CLI、可恢复会话与零配置工作区

> 本文是 [Product design: interactive CLI, resumable sessions, and zero-setup workspaces](../product-interactive-workspace.md) 的中文翻译。

## 概述

下一版本将让用户可以直接在普通本地项目的根目录中使用 `coding-agent`，无需记住子命令，也不必手动准备 Git 仓库。

它提供八项相互配合的能力：

1. 直接运行 `coding-agent` 即可打开交互式终端会话；
2. 在尚未成为 Git 仓库的目录中启动任务时，系统会安全地创建仓库、保护性的 `.gitignore` 和初始提交；
3. 输入 `/` 即可打开支持键盘选择的会话命令目录；
4. 进度行会标明每个工具的操作目标和可观察结果；
5. 高风险操作先显示简洁的审批摘要，并允许用户按需查看完整脱敏详情；
6. 对话类问题和只读问题可以直接返回 `ANSWERED`，无需伪造工作区修改；
7. 已完成的对话轮次可以跨终端进程持久化，并通过短引用或完整会话 ID 恢复；
8. 旧上下文会在超过配置的提示词预算之前自动压缩。

原有的 `coding-agent run`、`inspect-run` 和 `eval` 命令仍可用于脚本和可重复评测。

## 问题陈述

### 交互式终端

当前的单次命令适合自动化，却给探索式开发带来了不必要的摩擦。用户每次都必须重新输入工作区、模型和任务命令，而且没有持久入口可以提交后续请求或查看当前会话中创建的运行记录。

### Git 初始化

控制器需要 Git 基线来检测变更并生成可检查的最终差异。目前，非 Git 目录会触发配置错误。这个行为虽然安全，却会打断首次使用流程，并要求用户自行了解哪些初始化步骤既能保护密钥，又能得到可用基线。

### 交互清晰度

原始工具名称无法说明正在处理哪条路径或哪条命令，而在审批提示中直接输出完整 JSON 命令又太长，难以审查。同样，新用户在知道 `/help` 存在之前，无法发现隐藏在其中的命令。终端需要渐进式信息披露：简短且带目标的进度、摘要优先的审批，以及立即可见的命令目录。

### 对话连续性

交互式进程目前只在内存中保存历史。退出后会丢失助手的处理结果，后续进程无法继续同一段对话。长会话也需要由控制器管理的上下文策略；如果简单地不断重放越来越长的对话记录，最终会超出模型上下文，而且可能把旧审批或验证证据错误地带入一次新运行。

## 产品目标

- 不带参数运行 `coding-agent` 时，在当前目录打开终端 UI。
- 用户无需重启进程即可连续提交多个自然语言请求。
- 用户可以提出信息性问题并得到直接回答，同时不削弱编程任务的验证完成语义。
- 输入 `/` 后立即显示所有会话命令，并支持方向键选择和输入筛选。
- 使用紧凑且一致的视觉层级，让启动状态、智能体活动、工具结果、审批和会话结果都能被快速浏览。
- 模型/工具进度会标明正在处理的目录、文件、命令或输出，并报告简洁的可观察结果。
- 执行审批首先展示有边界的风险摘要，并允许用户按需查看完整脱敏参数。
- 每个提交的请求仍然对应一次有边界、独立记录的智能体运行。
- 会话为后续请求保留精简上下文，但不会削弱由控制器管理的预算、权限或完成检查。
- 用户可以列出已保存会话，并从其原始工作区恢复。
- 已完成的用户请求和助手结果在正常退出进程后仍会保留。
- 上下文压缩自动执行、过程可观察、大小有上限，并且不需要第二次模型调用。
- 持久化历史只是不可信上下文；它绝不会恢复审批、验证记录、工具状态或中断的控制器运行。
- 非 Git 工作区会在第一个任务开始前自动变为可用仓库。
- 除了生成的 `.gitignore` 所保护的文件，已有文件都会被纳入初始基线提交。
- 已有仓库和已有 `.gitignore` 文件不会被破坏性重写。
- 单次运行和评测工作流保持向后兼容。

## 非目标

- 全屏编辑器、鼠标 UI 或终端多路复用器。
- 模型逐 Token 流式输出；当前事件流仍是进度展示界面。
- 在一个交互式会话中并行执行任务或运行多个智能体。
- 恢复在工具调用或模型调用中途被中断的 `AgentEngine` 运行。
- 让多个交互式进程并发共享同一个会话。
- 自动选择或虚构 Git 作者身份。
- 当所选目录已经位于另一个 Git 仓库内部时，再初始化嵌套仓库。
- 替代操作系统级隔离；经过审批的命令仍以当前用户身份运行。

## 用户体验

### 在普通项目目录中首次运行

完成一次性安装后，用户进入项目目录并运行：

```powershell
coding-agent
```

CLI 会在修改目录之前校验模型配置和 Git 是否可用。如果该目录还不是仓库，它会报告每一步已经完成的初始化操作：

```text
  ↳ Setup  Initialized Git repository.
  ↳ Setup  Added protective and project-aware .gitignore rules.
  ↳ Setup  Created initial commit 1a2b3c4.
```

随后打开会话：

```text
╭─ Bounded Coding Agent
│  Workspace  C:\work\calculator
│  Model      deepseek-v4-flash · thinking disabled
│  Session    7e02e19a · new
╰─ / commands · /exit quit

❯ Fix the failing parser tests
```

任务运行时，模型和工具事件会持续显示。控制器进入终止状态后，UI 会输出状态和运行 ID，然后返回提示符。界面保持面向行的形式，因此终端的正常回滚查看、复制和审计工作流仍然可用。在等待模型响应时，一条临时的 `◇ Working…` 会让等待状态清晰可见；下一条动作或错误会替换该行，而不会制造永久噪声。

对于 `Who are you?` 这样的请求，模型会调用 `respond`，UI 会输出一条紧凑的 `◇ Answer`，然后显示运行引用。仓库相关问题可以先使用只读工具。如果当前运行已经修改工作区，控制器会拒绝 `respond`，仍然要求经过验证的 `finish` 或明确的受阻结果。

### 可读的进度

每个模型决策和工具结果都会标明操作目标，而不只是重复工具名称：

```text
● List  path=.
  └ ✓ List  path=. · 1 entry · 2 ms
● Create  path=index.html · 12640 chars
  └ ✓ Create  path=index.html · changed · 18 ms
● Run  program=node · cwd=. · purpose=verify · 2 args · inline code=3012 chars
  └ ✓ Run  program=node · exit=0 · 412 ms
```

文件内容、内联脚本、搜索词和输出正文不会直接回显到进度流中，而是用有边界的元数据表示。连续相同的动作会显示重复次数。

### 分层审批

执行审批首先显示动作、有边界的请求摘要、操作系统账户风险，以及精确操作的摘要值：

```text
╭─ Approval required · EXECUTION
│  Action   Run a local program
│  Request  program=node · cwd=. · purpose=verify · 2 args
│  Risk     Executes code with your operating-system account permissions.
│  Digest   1a9382237be7
╰─ y approve · d details · Enter deny
❯ Approve this digest? [y]es · [d]etails · [N]o:
```

输入 `d` 后，系统会以自动换行的 JSON 形式展示完整脱敏参数和完整摘要，然后再次询问。这样既能让默认提示易于浏览，也不会隐藏谨慎决策所需的信息。空输入仍表示拒绝。

### 已有 Git 仓库

已有仓库会立即打开。启动过程不会修改它的 `.gitignore`、索引、提交、分支或工作树。

### 脚本化单次运行

原有形式仍然受支持：

```powershell
coding-agent run --workspace C:\work\calculator "Fix the failing tests"
```

如果选中的目录不是仓库，它会使用同样的自动工作区初始化流程，然后以原有的状态专用退出码结束。

### 恢复对话

欢迎横幅和 `/session` 会显示短会话引用。后续终端可以在同一仓库中使用至少两个字符、且能唯一匹配的任意十六进制前缀继续该会话：

```powershell
coding-agent resume 7e
```

`coding-agent sessions` 会列出最近的会话，包括不会发生冲突的短引用、本地时间、轮次数和最近一次用户请求；`--workspace` 可以筛选列表。在 TUI 内，`/resume` 会打开一个方向键选择器，展示同样的识别信息；`/resume <prefix>` 则直接切换。存在歧义的前缀会被拒绝，并显示更长的候选引用。如果提供的工作区不是创建会话时记录的规范工作区，恢复请求也会被拒绝。这样可以防止一个仓库的历史被注入另一个仓库。

### 会话命令

初始终端 UI 支持：

| 命令 | 行为 |
|---|---|
| `/help` | 显示命令和交互规则。 |
| `/workspace` | 显示规范工作区路径。 |
| `/session` | 显示可恢复的短引用和完整会话 ID。 |
| `/resume [prefix]` | 选择或直接恢复当前工作区中的另一个会话。 |
| `/history` | 显示持久化的近期任务、状态和运行 ID。 |
| `/clear` | ANSI 控制可用时清空终端。 |
| `/exit`、`/quit` | 成功结束会话。 |

空行会被忽略。文件结束符会让程序成功退出。在提示符处按 `Ctrl+C` 会取消当前输入但保持会话开启；若要退出，仍需随后明确输入退出命令，行为清晰可预测。

在真实终端中，输入 `/` 后，命令候选会在按 Enter 之前显示。上下方向键移动反色高亮。第一次按 Enter 会把选中的命令补全到可编辑提示符中，但不会提交；用户仍可继续编辑，再次按 Enter 才会提交该行。普通字符会按命令前缀进行筛选，Backspace 用于编辑筛选词或在筛选为空时取消菜单，Escape 用于取消。重定向的标准输入仍采用脚本所需的确定性行模式行为。

## 对话模型

每次用户提交都会创建一个新的 `AgentEngine` 运行，拥有独立的运行 ID、预算、事件、制品、验证证据和终止结果。这样既保留可审计性，也避免控制器状态无限增长。

`ANSWERED` 表示目标在未修改工作区的情况下得到满足。它不能与 `SUCCEEDED` 混为一谈；后者仍然只用于具有最新验证证据和可检查差异的代码变更。

对于可视化 Web、游戏、动画、布局或交互请求，仅有命令行语法证据并不足够。最后一次修改后，当前 Web 文件必须在本地无头浏览器中成功渲染。用户会获得一个不透明的截图引用和导出命令以便检查；产品只把它描述为渲染证据，而不是对视觉质量的自动判断。

为了支持后续请求，用户级会话日志会保存经过脱敏的已完成用户请求、助手结果、状态、运行 ID 和变更路径名称。完整日志保留用于审计，而下一次请求只会得到一个有边界的派生视图。当视图超过目标大小时，控制器会确定性地把最早的原始轮次折叠为结构化记忆，并保留最新轮次的原文。系统不会信任模型生成的摘要，也不会仅为了压缩上下文而调用模型。

发生压缩时，UI 会进行提示。仓库内容仍然是权威状态，恢复的历史也会被明确标记为不可信。它不能授予权限、批准操作、恢复验证证据、取消当前预算限制，也不能被视为新运行的成功证据。

## 自动仓库初始化

### 生成的忽略策略

生成的规则首先保护可能的凭据，然后加入常见的本地文件、编辑器文件、操作系统文件和根据语言检测到的构建制品。规则至少涵盖：

- 各种 `.env` 文件，同时允许 `.env.example`；
- 已被 `PathPolicy` 拒绝的私钥和常见凭据文件名；
- 本地虚拟环境、缓存、IDE 状态和智能体本地状态；
- 检测到对应项目标记时产生的 Python、Node.js 或 C/C++ 构建制品。

如果非 Git 目录中已经存在 `.gitignore`，其内容会被保留，系统只会在带标签的区块中追加缺失的 coding-agent 规则。

### 初始提交

初始化会暂存所有未被忽略的文件，并创建：

```text
chore: initialize repository
```

提交使用用户已有的 Git 身份。如果 Git 无法解析身份信息，初始化会停止并给出配置命令；工具不会创建具有误导性的虚假作者。

### 安全异常

出现以下情况时，启动过程会停止且不会初始化：

- 目标不存在或不是目录；
- Git 不可用；
- 目标是外层仓库的子目录；
- 存在 `.git` 项，但它不是可用仓库；
- Git 身份预检查失败；
- 初始化、暂存或提交返回非零状态。

错误会报告失败的初始化阶段，但不会暴露模型凭据。Git 子进程只接收经过过滤的环境变量，并且绝不通过 Shell 运行。

## 成功标准

- 在已有仓库中直接运行 `coding-agent` 能够进入提示符。
- 输入 `/` 后立即显示全部命令；方向键能够明显高亮选项，Enter 会把选项补全到提示符而不执行。
- 输入一行自然语言后会启动一次真实的有边界运行，并最终返回提示符。
- 纯对话无需修改文件或经历被拒绝的 `finish` 循环，即可以 `ANSWERED` 结束；修改工作区后的 `respond` 会被拒绝。
- 每个文件/目录工具的进度行都会标明目标；命令进度会标明可执行文件、用途和退出码，但不输出内联代码。
- 审批界面初始内容保持有界；输入 `d` 会展示完整脱敏参数；未给出肯定回答时，按 Enter 表示拒绝。
- `/history` 会显示对应的运行 ID 和终止状态。
- 已完成的轮次可以在第二个 CLI 进程中通过会话引用恢复。
- 唯一短前缀可以从 CLI 或 TUI 恢复会话；有歧义的前缀会安全失败。
- 会话发现信息包含本地时间和最近一次用户请求。
- 从不同的规范工作区恢复会话时，会在智能体启动前被拒绝。
- 上下文始终低于配置的硬上限；旧轮次会自动压缩，同时保持近期轮次可读。
- 持久化 JSONL 已脱敏，且不包含审批 ID 或验证 ID。
- 退出终端时返回代码 `0`，并且不会改变仓库状态。
- 包含源文件的非 Git 目录会变为只有一个初始提交且工作树干净的 Git 仓库。
- 已有 `.gitignore` 内容会被保留。
- `.env`、私钥和生成制品不会进入初始提交。
- 对已有仓库再次执行初始化是无操作。
- 原有的 `run`、`inspect-run` 和 `eval` 测试继续通过。
